# Skill 目录

## 1. 基础设施

### `sdlc-scaffold`

初始化或检查代码库级 SDLC 治理结构。输出是新增文件清单、未修改文件清单和结构检查结果。它不创建单项变更目录和阶段产物。

## 2. 产物生成

### `capture-intent`

读取想法、工单或事故发现，生成结构化 `intent.md` 草稿。内容包括问题、期望结果、受影响对象、约束、范围外事项和未决问题。正式产物由发起人修正并由产品负责人接受。

### `compose-spec`

读取获批的 `intent.md`，加载适用政策 Skills，生成或校验完整的 `spec.md`。内容包括目标、范围、用户场景、功能需求、系统边界、非功能要求、政策约束、验收条件、风险和批准记录。

## 3. 领域政策与标准

### `brand-guidelines`

输出适用的品牌约束、品牌验收条件、违规项和需要品牌负责人处理的冲突。

### `compliance-policy`

输出合规义务、证据要求、政策冲突和需要人工裁决的问题。

### `ux-standards`

输出用户流程、界面状态、可访问性检查项和体验验收条件。

### `security-policy`

输出通用安全约束、威胁关注点、安全验收条件和升级条件。

### `api-design-conventions`

输出 API 契约约束和设计检查结果，覆盖路径、字段、版本、Schema、分页、错误格式和兼容性。

## 4. 专项验证

### `secure-api-review`

输出 API 安全要求、按严重程度排列的问题和检查脚本结果，覆盖身份认证、输入校验、审计事件和 PII。

## 5. 共同要求

每个 Skill 开发时都需要写清触发条件、排除条件、输入、输出、正式产物关系、人工负责人和政策来源。需要确定执行的规则必须配套 Hook 或 CI 检查。每次 Skill 变更都要通过评估用例，并由对应负责人评审。
